# Aviator History Recorder

Локальный проект для сохранения результатов браузерной игры Aviator:

- Chrome Extension перехватывает события игры внутри кросс-доменного iframe;
- результаты временно складываются в локальную очередь расширения;
- Python/FastAPI принимает данные;
- MySQL 8.4 хранит историю;
- phpMyAdmin используется для просмотра БД.

## Порты

По умолчанию используются свободные порты, не пересекающиеся с указанными занятыми:

| Сервис | URL/порт хоста | Порт внутри Docker |
|---|---:|---:|
| API | `http://localhost:8010` | `8000` |
| MySQL | `localhost:3310` | `3306` |
| phpMyAdmin | `http://localhost:8090` | `80` |

Порты меняются в `.env`.

## 1. Запуск Docker

```bash
cp .env.example .env
```

Обязательно поменяйте пароли MySQL в `.env`, затем:

```bash
docker compose up -d --build
```

Проверка API:

```text
http://localhost:8010/api/v1/health
```

Веб-интерфейс анализа:

```text
http://localhost:8010/
```

phpMyAdmin:

```text
http://localhost:8090
```

Параметры входа в phpMyAdmin берутся из `.env`:

- сервер: `mysql`;
- пользователь: значение `MYSQL_USER`;
- пароль: значение `MYSQL_PASSWORD`.

## 2. Установка Chrome Extension

1. Откройте `chrome://extensions`.
2. Включите «Режим разработчика».
3. Нажмите «Загрузить распакованное расширение».
4. Выберите папку `extension`.
5. Откройте popup расширения.
6. Укажите `http://localhost:8010`.
7. Нажмите «Проверить API», затем «Сохранить».

После этого откройте страницу Aviator на `pm.by` и оставьте вкладку открытой.

## Как работает сбор

Страница оператора содержит кросс-доменный игровой iframe. Поэтому расширение запускает два content script во всех HTTPS/HTTP-фреймах:

- MAIN-world hook перехватывает входящие сообщения WebSocket и ответы fetch/XHR;
- ISOLATED-world bridge передаёт только найденные результаты в service worker;
- DOM-наблюдатель служит резервным способом и принимает только стабилизировавшиеся значения вида `1.23x` внутри элементов истории/результатов.

Фактический сбор включается только тогда, когда верхняя вкладка распознана как страница Aviator. Сетевые cookies, JWT и параметры авторизации в БД не сохраняются.

## Диагностика

Если таблица `game_results` остаётся пустой:

1. Откройте popup расширения.
2. Включите «Диагностика протокола».
3. Сыграйте или дождитесь нескольких завершённых раундов.
4. Посмотрите таблицу `diagnostic_samples`.

Диагностические строки обрезаются и очищаются от JWT, Bearer-токенов, session/token-полей и query-параметров URL.

После определения точного формата сообщений диагностику лучше выключить.

## API

### Получить результаты

```bash
curl "http://localhost:8010/api/v1/results?limit=100&offset=0"
```

### Получить диагностические образцы

```bash
curl "http://localhost:8010/api/v1/diagnostics/samples?limit=100&offset=0"
```

## Таблицы

### `game_results`

- `event_id` — UUID события расширения;
- `round_id` — ID раунда, если найден в протоколе;
- `multiplier` — итоговый коэффициент;
- `happened_at` — время раунда, если найдено;
- `captured_at` — время фиксации расширением;
- `source` — `websocket`, `fetch`, `xhr` или `dom`;
- `metadata` — безопасные технические признаки парсинга.

### `diagnostic_samples`

Содержит очищенные фрагменты неизвестных сообщений, нужные для адаптации парсера под конкретную версию провайдера.

## Безопасность

- Не публикуйте сохранённый HTML игры: в URL iframe могут присутствовать краткоживущие игровые токены.
- API открыт без авторизации. Не публикуйте порт API в интернет.
- Расширение имеет широкое разрешение на страницы, потому что игровой iframe после launch-URL может перейти на домен провайдера, заранее неизвестный manifest-файлу. В коде сбор ограничен вкладкой Aviator.

## Веб-интерфейс анализа

На главной странице API доступен график накопительного результата по всей таблице `game_results`.

Для введённого значения `x` каждый раунд рассчитывается так:

- `multiplier > x`: к текущему результату прибавляется `x - 1`;
- `multiplier <= x`: из текущего результата вычитается `1`.

Ниже графика показываются:

- общее число результатов;
- количество положительных и отрицательных результатов;
- `отрицательные / положительные * (x - 1)`;
- `положительные - отрицательные * (x - 1)`;
- фактический итог линии графика: `положительные * (x - 1) - отрицательные`.

Данные автоматически обновляются каждые 5 секунд. Для больших таблиц статистика считается по всем строкам, а количество точек на графике ограничивается для сохранения производительности.

API расчёта:

```bash
curl "http://localhost:8010/api/v1/analysis?x=2&max_points=5000"
```
